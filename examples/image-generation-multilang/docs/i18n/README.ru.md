# Генерация и редактирование изображений через API на шести языках: Python, Node.js, C++, Go, Rust и PHP

Это подробное руководство по открытому многоязычному демонстрационному проекту для разработчиков. Каждый из шести примеров выполняет один и тот же практический сценарий: отправляет текстовый запрос в endpoint OpenAI-compatible Images API `/images/generations`, сохраняет полученное изображение локально, а затем загружает именно этот файл в `/images/edits` вместе с инструкцией по изменению. Так можно изучить обе операции по шагам, проверить реальный обмен данными и сравнить подходы разных экосистем.

Проект предназначен для обучения и проверки интеграций; это не официальный SDK OpenAI и не готовый к публичному использованию производственный сервис. По умолчанию примеры обращаются к независимой платформе [AI-ROUTER](https://ai-router.dev/ru), однако базовый URL настраивается, поэтому клиент можно направить на другой шлюз с совместимым API. Доступность моделей, разрешения, квоты, цены, допустимые размеры и форматы ответов зависят от аккаунта и текущей конфигурации upstream-сервиса. Наличие названия модели в примере не означает, что она доступна каждому пользователю.

## Для чего нужен этот проект

- **Понять полный цикл работы с изображением:** создать черновик по тексту, сохранить его и отправить тот же файл на редактирование с новой инструкцией.
- **Разобраться в контракте Images API:** увидеть Bearer-аутентификацию, JSON-запрос генерации, multipart-загрузку для редактирования, разбор ответа и сохранение результата.
- **Сравнить архитектуру шести реализаций:** процессы и набор полей одинаковы, различаются способы конфигурирования, HTTP-транспорт, типизация и организация CLI.
- **Взять клиент за основу прототипа:** встроить его в веб-сервис, worker, задачу очереди, пакетную обработку или внутренний инструмент. Перед открытием доступа конечным пользователям потребуется собственная защита и контроль затрат.

Полный сценарий выполняет как минимум два запроса к API изображений — генерацию и редактирование. Перед запуском уточните тариф, списание средств и правила хранения данных в своём аккаунте.

## Архитектура: шесть языков, одна последовательность операций

Примеры разделяют конфигурацию, HTTP-клиент, бизнес-сценарий и CLI. Благодаря этому транспорт можно заменить или использовать из приложения без копирования логики аргументов командной строки. При этом каждый каталог следует обычным для соответствующего языка соглашениям.

| Язык | Модули и их назначение | Фактический способ запуска | Что показывает реализация |
| --- | --- | --- | --- |
| **Python** | `image_demo/config.py` загружает и проверяет настройки; `client.py` использует стандартный `urllib` для JSON, multipart, разбора ответа и получения изображения по URL; `workflow.py` сохраняет результат генерации, вызывает редактирование и сохраняет итог; `cli.py` отвечает за параметры и вывод. | В каталоге `python`: `python main.py --prompt ... --edit-prompt ...`. Одна команда выполняет весь сценарий. | Минимальная зависимость от среды: только стандартная библиотека, удобно для скриптов и пакетных задач. |
| **Node.js** | `src/config.mjs` хранит общие настройки; `src/client.mjs` инкапсулирует встроенный `fetch`; `src/workflow.mjs` связывает операции; `src/cli.mjs` реализует CLI; `test/` использует встроенный `node:test`. | В каталоге `nodejs`: `npm run demo -- --prompt ... --edit-prompt ...`. | Нет сторонних runtime-пакетов; пример подходит для JavaScript backend, очередей и serverless-среды. |
| **C++** | `include/image_client.hpp` задаёт переиспользуемый интерфейс; `src/image_client.cpp` использует libcurl для запросов и multipart; `src/main.cpp` является CLI и композицией двух шагов; CMake отдельно собирает библиотеку, программу и офлайн-тесты. | В каталоге `cpp` собрать CMake и запустить `imagegen --prompt ... --edit-prompt ...`. | Показывает границы C++17-клиента на базе libcurl и CMake. |
| **Go** | `internal/config` читает значения окружения; `internal/client` отвечает за `net/http`, `encoding/json`, multipart и декодирование; `cmd/imagegen` разбирает флаги и координирует workflow; тест клиента использует `httptest`. | В каталоге `go`: `go run ./cmd/imagegen --prompt ... --edit-prompt ...`. | Реализация на стандартной библиотеке подходит для небольших служб, CLI и фоновых worker-процессов. |
| **Rust** | `config.rs` загружает секрет и адрес; `client.rs` использует `reqwest` и `serde`; `types.rs` описывает ответ; `workflow.rs` соединяет операции; `artifacts.rs` сохраняет файлы; `main.rs` через `clap` предоставляет `generate`, `edit`, `workflow`. | В каталоге `rust`: `cargo run --release -- workflow ...`; генерацию и редактирование также можно вызвать отдельно. | Демонстрирует типизированный асинхронный HTTP-клиент и разделение сети, файловой системы и сценария приложения. |
| **PHP** | `Config` читает окружение; `ImageClient` реализует cURL-запросы; `ImageData` нормализует ответ; `ArtifactStore` сохраняет байты; `Workflow` выполняет два шага; `bin/image-demo.php` предоставляет команды CLI. | В каталоге `php`: `php bin/image-demo.php workflow ...`; доступны также `generate` и `edit`. | Мини-клиент без обязательных runtime-пакетов Composer; нужны расширения PHP cURL и JSON. |

В каждом workflow первое изображение записывается на диск **до** запроса редактирования. Если второй запрос завершится ошибкой, исходный результат остаётся доступен для проверки и отдельного повторного запуска. Подробности слоёв и точки расширения описаны в [руководстве по архитектуре](../ARCHITECTURE.md); правила синхронизации нового языка — в [руководстве для участников](../../CONTRIBUTING.md).

## Контракт OpenAI-compatible Images API

Базовый URL по умолчанию: `https://api.ai-router.dev/v1`. Переменная `base_url` в примерах включает `/v1`; путь endpoint добавляется к ней. К запросам генерации и редактирования прикладывается ключ аккаунта в заголовке Bearer.

### Шаг 1. Текст в изображение: `POST /images/generations`

Запрос передаётся как `application/json`. Это иллюстративный вариант совместимой структуры; набор поддерживаемых дополнительных полей зависит от конкретного шлюза и аккаунта:

```http
POST https://api.ai-router.dev/v1/images/generations
Authorization: Bearer $AI_ROUTER_API_KEY
Content-Type: application/json
```

```json
{
  "model": "gpt-image-2",
  "prompt": "Небольшая стеклянная оранжерея на крыше после дождя, мягкий рассветный свет",
  "size": "1024x1024",
  "n": 1,
  "response_format": "b64_json"
}
```

Клиент извлекает первую картинку из массива `data`. Реализации умеют декодировать `b64_json`; при URL-ответе они могут отдельно скачать изображение. Base64 упрощает передачу результата между двумя этапами и не требует отдельной загрузки по временному URL. Фактический формат ответа определяется сервисом.

### Шаг 2. Изображение в изображение: `POST /images/edits`

Редактирование отправляется как `multipart/form-data`. Главный смысл этого шага — загрузить файл, созданный первым запросом, через поле `image`; текстовая инструкция сама по себе не является редактированием существующей картинки.

| Поле | Назначение |
| --- | --- |
| `model` | ID доступной аккаунту модели, которая поддерживает редактирование изображений. |
| `prompt` | Инструкция, что изменить; полезно явно указать, какие объекты и композицию нужно сохранить. |
| `size` | Необязательный желаемый размер. Например, `1024x1024`, если выбранная модель и аккаунт его поддерживают. |
| `response_format` | В демо предпочтителен `b64_json`; конфигурация сервиса может выдавать URL. |
| `image` | Обязательное поле-файл; передаётся локально сохранённый результат генерации. |

Ответ имеет совместимую структуру `data` с результатом изображения. Полный список полей см. в [общем описании API-контракта](../API_CONTRACT.md).

### Выбор модели и границы совместимости

Параметр `--model`, `AI_ROUTER_MODEL` или эквивалент передаёт строковый ID модели шлюзу. Можно попробовать `gpt-image-2`, `gpt-image-2.5`, `gpt-image-2.5-flare`, `gpt-image-2.5-burst` только если конкретная модель видна в списке вашего аккаунта и допускает нужную операцию. Примеры не обходят разрешения, не резервируют доступ и не гарантируют стабильность названий, цены или поддерживаемых размеров. Значение `1024x1024` — лишь значение по умолчанию в демо, а не обещание совместимости с любой моделью.

Термин «OpenAI-compatible» описывает сходную форму endpoint и запросов, которая помогает переносить интеграционный шаблон между шлюзами. Он не означает, что AI-ROUTER является продуктом OpenAI или что все необязательные поля и модели ведут себя одинаково. Проверяйте актуальную документацию выбранного сервиса.

## Переменные окружения и настройки

Корневой `.env.example` — образец, а не автоматически загружаемый файл. CLI каждого языка читает переменные из своего процесса; экспортируйте их в shell или используйте доверенный dotenv-загрузчик. Не добавляйте реальный секрет в Git.

Общий стартовый набор:

```bash
export AI_ROUTER_API_KEY="ваш-ключ"
export AI_ROUTER_BASE_URL="https://api.ai-router.dev/v1"
export AI_ROUTER_MODEL="gpt-image-2"
export AI_ROUTER_SIZE="1024x1024"
```

Фактические имена, прочитанные кодом каждого примера:

| Реализация | Переменные ключа | Базовый URL | Модель, размер и таймаут |
| --- | --- | --- | --- |
| Python | `IMAGE_API_KEY`, `OPENAI_API_KEY`, `AI_ROUTER_API_KEY` | `IMAGE_API_BASE_URL`, `AI_ROUTER_BASE_URL` | `IMAGE_MODEL` / `AI_ROUTER_MODEL`; `IMAGE_SIZE` / `AI_ROUTER_SIZE`; `IMAGE_QUALITY`; `IMAGE_TIMEOUT_SECONDS` в секундах |
| Node.js | `IMAGE_API_KEY`, `OPENAI_API_KEY`, `AI_ROUTER_API_KEY` | `IMAGE_API_BASE_URL`, `AI_ROUTER_BASE_URL` | `IMAGE_MODEL` / `AI_ROUTER_MODEL`; `IMAGE_SIZE` / `AI_ROUTER_SIZE`; `IMAGE_QUALITY`; `IMAGE_TIMEOUT_MS` в миллисекундах |
| C++ | `OPENAI_API_KEY`, `AI_ROUTER_API_KEY` | `OPENAI_BASE_URL`, `AI_ROUTER_BASE_URL` | `IMAGE_MODEL` / `AI_ROUTER_MODEL`; `IMAGE_SIZE` / `AI_ROUTER_SIZE`; `IMAGE_RESPONSE_FORMAT`; `IMAGE_API_TIMEOUT` / `AI_ROUTER_IMAGE_TIMEOUT` в секундах |
| Go | `OPENAI_API_KEY`, `AI_ROUTER_API_KEY` | `OPENAI_BASE_URL`, `AI_ROUTER_BASE_URL` | `IMAGE_MODEL` / `AI_ROUTER_MODEL`; `IMAGE_SIZE` / `AI_ROUTER_SIZE`; `IMAGE_RESPONSE_FORMAT`; `IMAGE_API_TIMEOUT` / `AI_ROUTER_IMAGE_TIMEOUT` в секундах |
| Rust | `AI_ROUTER_API_KEY`, `OPENAI_API_KEY` | `AI_ROUTER_BASE_URL` | `AI_ROUTER_TIMEOUT_SECONDS`; подкоманды принимают модель и размер, переменные модели/размера также поддерживаются CLI |
| PHP | `AI_ROUTER_API_KEY`, `OPENAI_API_KEY` | `AI_ROUTER_BASE_URL` | `AI_ROUTER_TIMEOUT_SECONDS`; модель и размер передаются CLI либо используются его стандартные значения |

CLI-флаги обычно заменяют стандартные параметры окружения. Важное отличие: PHP не имеет `--api-key`, поэтому передайте секрет через окружение. В Rust адрес передаётся через `--base-url`, а `--model` и `--size` относятся к выбранной подкоманде.

## Установка и запуск по шагам

Команды ниже выполняются из корня репозитория; переходите в каталог нужного языка. Полный цикл отправляет два запроса API. Локальные тесты не требуют настоящего ключа и не выполняют генерацию.

### Python — версия 3.10 или новее

Внешние runtime-зависимости не нужны: транспорт использует стандартную библиотеку Python. Создайте окружение:

```bash
cd marketing/image-generation-multilang/python
python -m venv .venv
```

Активируйте его подходящей для вашей системы командой:

```bash
# Linux или macOS
source .venv/bin/activate

# Windows PowerShell
.\.venv\Scripts\Activate.ps1
```

Установите переменную ключа и выполните генерацию с последующим редактированием:

```bash
export IMAGE_API_KEY="ваш-ключ"
python main.py \
  --prompt "Стеклянная оранжерея на крыше после дождя, кинематографичная фотография" \
  --edit-prompt "Сделай свет тёплым, как на закате, сохрани архитектуру оранжереи" \
  --output-dir ./outputs
```

В PowerShell используйте `$env:IMAGE_API_KEY = "ваш-ключ"` и обычные правила переноса команд. По умолчанию появятся два файла в `outputs/`: исходное изображение `generated` и результат `edited`; расширение зависит от формата изображения. Командой `python -m pip install -e .` можно дополнительно установить консольную точку входа `image-demo`. Проверка без API: `python -m unittest discover -s tests -v`.

### Node.js — версия 18.17 или новее

В каталоге нет runtime-зависимостей из npm. Установив Node.js, сначала запустите локальные тесты:

```bash
cd marketing/image-generation-multilang/nodejs
npm test
```

Затем укажите ключ и запускайте двухэтапный сценарий:

```bash
export AI_ROUTER_API_KEY="ваш-ключ"
npm run demo -- \
  --prompt "Стеклянная оранжерея на крыше после дождя, кинематографичная фотография" \
  --edit-prompt "Сделай свет тёплым, как на закате, сохрани архитектуру оранжереи" \
  --model gpt-image-2
```

В PowerShell задайте `$env:AI_ROUTER_API_KEY`. Результаты по умолчанию: `nodejs/outputs/generated.png` и `nodejs/outputs/edited.png`. Можно также указать `--size`, `--quality`, `--base-url`, `--timeout` в миллисекундах и `--output-dir`. `npm test` проверяет конфигурацию без платных запросов.

### C++17 — CMake 3.20+ и libcurl

Потребуются компилятор с поддержкой C++17, CMake и файлы разработки libcurl. В Windows с vcpkg установите библиотеку:

```powershell
vcpkg install curl:x64-windows
```

Для vcpkg при настройке CMake добавьте путь к `vcpkg.cmake`; общий процесс сборки и офлайн-проверки:

```bash
cd marketing/image-generation-multilang/cpp
cmake -S . -B build -DBUILD_TESTING=ON
cmake --build build --config Release
ctest --test-dir build --output-on-failure
```

Перед запуском установите `AI_ROUTER_API_KEY`:

```bash
export AI_ROUTER_API_KEY="ваш-ключ"
./build/imagegen \
  --base-url https://api.ai-router.dev/v1 \
  --model gpt-image-2 \
  --prompt "Стеклянная оранжерея на крыше после дождя" \
  --edit-prompt "Добавь мягкий золотистый свет заката, сохрани форму здания" \
  --output generated.png --edited-output edited.png
```

В Visual Studio с многоконфигурационным генератором исполняемый файл обычно находится по пути `build/Release/imagegen.exe`. CTest запускает офлайн-тесты и не требует API key. CLI дополнительно принимает `--size`, `--response-format`, `--timeout` и пути файлов.

### Go — версия 1.22 или новее

Клиент использует стандартную библиотеку Go, дополнительных библиотек для выполнения не нужно:

```bash
cd marketing/image-generation-multilang/go
go test ./...
go vet ./...
```

Полный запуск с генерацией и редактированием:

```bash
export AI_ROUTER_API_KEY="ваш-ключ"
go run ./cmd/imagegen \
  --base-url https://api.ai-router.dev/v1 \
  --model gpt-image-2 \
  --prompt "Стеклянная оранжерея на крыше после дождя" \
  --edit-prompt "Добавь мягкий золотистый свет заката, сохрани форму здания" \
  --output generated.png --edited-output edited.png
```

По умолчанию файлы записываются в текущий каталог как `generated.png` и `edited.png`. Тесты используют локальный `httptest.Server` и не вызывают платные модели.

### Rust — стабильная версия Rust/Cargo

Cargo скачивает зависимости из `Cargo.toml`, поэтому первая сборка может потребовать доступ к crates.io. Из каталога проекта:

```bash
cd marketing/image-generation-multilang/rust
export AI_ROUTER_API_KEY="ваш-ключ"
```

Сначала сгенерировать, сохранить, затем отредактировать тот же файл можно одной командой:

```bash
cargo run --release -- workflow \
  --prompt "Стеклянная оранжерея на крыше после дождя" \
  --edit-prompt "Добавь тёплые подвесные лампы, сохрани композицию" \
  --model gpt-image-2 --size 1024x1024 \
  --generated output/generated.png \
  --edited output/edited.png
```

Родительские каталоги создаются автоматически. Отдельные операции доступны через `cargo run -- generate --prompt ... --output ...` и `cargo run -- edit --image ... --prompt ... --output ...`. `cargo test` позволяет проверить сборку и тестовые цели; клиент запрашивает `b64_json` и распознаёт ответ со ссылкой на изображение.

### PHP — версия 8.1+, расширения cURL и JSON

Для запуска демонстрации Composer-пакеты не нужны: в проекте есть простой autoloader. Убедитесь, что расширения включены именно в PHP CLI:

```bash
cd marketing/image-generation-multilang/php
php -m
export AI_ROUTER_API_KEY="ваш-ключ"
```

Запуск всей последовательности:

```bash
php bin/image-demo.php workflow \
  --prompt "Стеклянная оранжерея на крыше после дождя" \
  --edit-prompt "Добавь тёплые подвесные лампы, сохрани композицию" \
  --model gpt-image-2 --size 1024x1024 \
  --generated output/php-generated.png \
  --edited output/php-edited.png
```

Также существуют команды `generate` и `edit`. Значения по умолчанию сохраняются в `output/php-generated.png` и `output/php-edited.png`; адрес API читается из `AI_ROUTER_BASE_URL`. Секрет читается из `AI_ROUTER_API_KEY` или `OPENAI_API_KEY`, но не из флага CLI. Если вы интегрируете классы в Composer-приложение, можно использовать PSR-4 из `composer.json` и выполнить `composer dump-autoload`.

## Созданные файлы и стоимость

В результате получаются черновик text-to-image и отдельная отредактированная версия. Пути задаются параметрами CLI или используются значения по умолчанию конкретного языка. Типичный `.gitignore` игнорирует каталоги результатов, но перед коммитом проверьте `git status`, особенно если изображения содержат личные либо клиентские данные.

Автоматических повторов в примерах нет. Такой выбор намеренный: повтор генерации или редактирования может создать ещё один оплачиваемый запрос. Если редактирование не удалось, не удаляйте успешный черновик; сначала выясните причину, а затем запускайте только нужную операцию снова.

## Устранение неполадок

| Ошибка или симптом | Что проверить |
| --- | --- |
| `401`, `403`, отсутствует ключ | Переменная должна быть установлена в том процессе/shell, из которого запущен CLI. Имена переменных различаются между языками. Проверьте действительность ключа и доступ аккаунта; не помещайте секрет в публичный лог. |
| Модель не найдена или запрещена | Сверьте точный ID со списком аккаунта и проверьте поддержку обоих endpoint — генерации и редактирования. |
| Неподдерживаемый размер или качество | Используйте допустимое значение для конкретной модели и аккаунта. Начните с `1024x1024`, только если документация сервиса подтверждает его. |
| Таймаут или ошибка соединения | Проверьте base URL, TLS, прокси, доступность сети и единицы таймаута. У Node.js значение задано в миллисекундах, у большинства остальных примеров — в секундах. Не повторяйте запросы вслепую при неясном статусе оплаты. |
| В ответе нет картинки / ошибка base64 | Проверьте фактическую форму ответа и совместимость шлюза. Некоторые клиенты умеют получить изображение по URL, но временная ссылка может истечь или стать недоступной. |
| Генерация прошла, редактирование нет | Убедитесь, что исходный файл существует, читается и не пуст; проверьте `edit-prompt` и поддержку редактирования выбранной моделью. Сохраните черновик и диагностируйте только второй этап. |
| CMake не обнаруживает CURL | Установите libcurl development package и проверьте CMake toolchain/config. Для vcpkg добавьте `vcpkg.cmake` при конфигурации. |
| Не компилируется Rust | Проверьте установку stable Rust/Cargo и доступность реестра зависимостей; сначала выполните `cargo check` и изучите вывод. |
| PHP сообщает об отсутствующих функциях cURL | Включите расширение `curl` в `php.ini`, который использует CLI. Конфигурация PHP для командной строки может отличаться от настройки веб-сервера. |

## Безопасность, приватность и ответственное использование

- Храните API key в окружении или менеджере секретов; не добавляйте его в Git, shell history, issue или скриншот. В публичном веб-приложении нельзя передавать сервисный ключ в браузер.
- Используйте HTTPS и проверяйте, что базовый URL принадлежит ожидаемому сервису. Конкретные правила обработки, логирования и хранения изображений нужно уточнять в условиях и документации выбранного сервиса.
- Промпты и входные/сгенерированные изображения могут раскрывать личные или коммерческие сведения. Загружайте только данные, на обработку которых у вас есть право; ограничивайте доступ и срок хранения локальных файлов.
- Считайте URL из ответа внешним вводом. Для публичного сервиса нужны allow-list хостов, ограничения перенаправлений, размера и времени загрузки, проверка MIME-типа и фактического формата — это помогает снизить риск SSRF и чрезмерного потребления ресурсов.
- До открытия endpoint конечным пользователям добавьте аутентификацию, квоты, rate limiting, модерацию, отмену запросов, метрики и безопасное логирование с минимизацией данных. Демо не предоставляет эти функции как готовую гарантию.
- Соблюдайте правила сервиса, права на исходные изображения и местное законодательство; перед публикацией проверяйте качество и допустимость результата.

Практические замечания собраны в [руководстве по безопасности](../SECURITY.md).

## Как развивать демонстрацию для своего продукта

1. **Перенесите хранение из локальной папки.** Замените запись файла на объектное хранилище с ограниченным доступом, шифрованием и сроком жизни, сохранив ясную последовательность `generate → save → edit → save`.
2. **Ограничьте входные данные и затраты.** Задайте максимальную длину промпта, тип и размер файла, квоты по пользователю и модели; передавайте отмену запроса и таймауты по всей цепочке.
3. **Добавляйте повторы только осознанно.** Используйте ограниченный backoff лишь для безопасных повторных ошибок и только после проверки семантики тарификации и идемпотентности.
4. **Наблюдайте за системой, не собирая лишнего.** Сохраняйте request ID, фазу, статус и длительность; редактируйте промпты и персональные данные при логировании; никогда не журналируйте ключ.
5. **Закрепляйте контракт тестами.** При расширении параметров синхронно меняйте общее описание, все нужные реализации и офлайн-тесты. Для multipart применяйте локальный mock server, чтобы не расходовать квоту на каждое изменение.
6. **Добавляйте новые языки постепенно.** Создайте отдельные модули конфигурации, транспорта, workflow и CLI; тестируйте точки обмена данными. Не помещайте HTTP-код в парсер аргументов и не предполагайте, что vendor-specific поля одинаковы у всех шлюзов.

См. также [архитектуру](../ARCHITECTURE.md), [контракт](../API_CONTRACT.md) и [примеры промптов](../../examples/prompts.md), которые можно повторить на каждом языке.
