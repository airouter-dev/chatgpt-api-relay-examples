# واجهة توليد الصور وتحريرها بالذكاء الاصطناعي: أمثلة بست لغات برمجة

يشرح هذا الدليل كيفية إنشاء صورة من وصف نصي، ثم تعديل الصورة الناتجة بإرسالها كمدخل إلى واجهة التحرير. يضم المشروع تطبيقات مرجعية مستقلة بـ **Python وNode.js وC++ وGo وRust وPHP**، وتستخدم مسارات متوافقة مع Images API عبر AI-ROUTER. يتبع كل مثال دورة عملية واضحة: إنشاء مسودة، حفظها محلياً، ثم إرسال الملف إلى `images/edits` مع تعليمات تعديل جديدة.

> AI-ROUTER خدمة مستقلة تقدم واجهة متوافقة مع OpenAI، وليست منتجاً من OpenAI ولا تمثلها. ذكر أسماء النماذج في هذا المشروع لا يعني أنها متاحة لكل حساب، كما أن الأسعار والحصص والأحجام والحقول الاختيارية تخضع لإعداد الحساب والخدمة الحالية. تحقّق من النماذج المتاحة لحسابك قبل إجراء طلبات قد تكون مدفوعة.

**الصفحة الرئيسية باللغة العربية:** [AI-ROUTER](https://ai-router.dev/ar). هذا المستودع مثال تقني تعليمي؛ لا يضمن نتيجة توليد بعينها أو إتاحة نموذج أو تحسناً في ترتيب الموقع ضمن نتائج البحث.

## ما الذي يفعله المثال؟

ينفذ البرنامج عمليتين منفصلتين ضمن مسار واحد:

1. يرسل الوصف إلى `POST /v1/images/generations` ليطلب صورة جديدة.
2. يحوّل الصورة المستلمة إلى ملف محلي. تتعامل الأمثلة مع حقل `b64_json`، كما تقبل بعض التطبيقات استجابة `url` وفق ما تسمح به البوابة.
3. يرفع الملف المحفوظ إلى `POST /v1/images/edits` بصيغة `multipart/form-data` مع وصف يحدد التغيير المطلوب.
4. يحفظ النتيجة المعدلة في ملف مستقل، مع الاحتفاظ بالمسودة الأصلية للمراجعة أو المقارنة أو استخدامها في تعديل آخر.

هذا المسار مفيد عند تقييم واجهة توليد الصور: فهو يوضح تحويل النص إلى صورة ثم تحويل صورة موجودة إلى نسخة معدلة داخل التطبيق نفسه. عملية التعديل حقيقية وليست صورة افتراضية؛ فالطلب الثاني يستخدم الملف الناتج من الطلب الأول.

## تصميم يسهل فهمه وتوسيعه

تفصل التطبيقات بين مسؤوليات الإعداد والاتصال والتنسيق وواجهة الطرفية:

| الطبقة | الدور |
| --- | --- |
| الإعدادات | قراءة مفتاح API وعنوان الخدمة والنموذج والحجم والمهلة من البيئة أو خيارات سطر الأوامر. |
| عميل HTTP | بناء JSON أو نموذج multipart، وإضافة المصادقة، ومعالجة الأخطاء وتحويل الرد إلى بايتات صورة. |
| سير العمل | تنسيق الإنشاء ثم الحفظ ثم التعديل ثم حفظ النسخة الجديدة، من دون تفاصيل النقل الشبكي. |
| واجهة CLI | استقبال مدخلات المستخدم وإظهار مسارات الصور التي تم حفظها. |

يسمح هذا الفصل بنقل العميل إلى خادم ويب أو عامل خلفي أو مهمة ضمن طابور أو تطبيق سطح مكتب من دون نسخ منطق HTTP إلى الواجهة. راجع أيضاً [`ARCHITECTURE.md`](../ARCHITECTURE.md) و[`API_CONTRACT.md`](../API_CONTRACT.md) و[`SECURITY.md`](../SECURITY.md) للتعرف على التصميم والعقد الأمني المشترك.

## اختيار اللغة المناسبة

تقدم المجلدات الستة السلوك نفسه بأدوات شائعة في كل منظومة. اختر اللغة التي تناسب بيئة تطبيقك؛ فاللغة وحدها لا تغير جودة نموذج الصور.

| اللغة | النقل ونقطة التشغيل | ملائمة كبداية لـ |
| --- | --- | --- |
| Python | مكتبة `urllib`؛ الأمر `python main.py` | السكربتات والدفاتر والأتمتة دون اعتماد إضافي وقت التشغيل |
| Node.js | واجهات `fetch` و`FormData` و`Blob`؛ الأمر `npm run demo --` | خدمات JavaScript والمهام الخلفية وبيئات serverless |
| C++ | مكتبة libcurl؛ برنامج `imagegen` | البرامج الأصلية والبيئات التي تتطلب تحكماً صريحاً بالاعتمادات |
| Go | مكتبة `net/http`؛ الأمر `go run ./cmd/imagegen` | الخدمات الصغيرة وعمال المعالجة باستخدام المكتبة القياسية |
| Rust | `reqwest` و`serde` و`clap`؛ الأمر `cargo run -- workflow` | العملاء ذات الأنواع الصريحة والخدمات غير المتزامنة |
| PHP | امتدادا cURL وJSON؛ الأمر `php bin/image-demo.php workflow` | تطبيقات PHP ومهام سطر الأوامر |

يمكن تشغيل كل تطبيق بمفرده. وللمقارنة العملية، استخدم الحساب والنموذج والحجم والوصفين نفسيهما؛ واحرص على الفصل بين سلوك العميل ونتيجة الخدمة وإعدادات الحساب.

## التجهيز: مفتاح API وعنوان الخدمة والنموذج

أنشئ مفتاحاً من [الموقع العربي لـ AI-ROUTER](https://ai-router.dev/ar)، واحتفظ به في متغير بيئة أو مدير أسرار. عنوان API الافتراضي للأمثلة هو `https://api.ai-router.dev/v1`. لا تضع المفتاح في مستودع GitHub أو لقطة شاشة أو سجلات CI أو تطبيق متصفح عام. في تطبيق الويب، أرسل الطلب من خادمك بدلاً من كشف السر للمستخدم.

مثال في Bash:

```bash
export AI_ROUTER_API_KEY="your-key"
export AI_ROUTER_BASE_URL="https://api.ai-router.dev/v1"
export AI_ROUTER_MODEL="gpt-image-2"
```

تقبل بعض البرامج أسماء بيئة بديلة مثل `IMAGE_API_KEY` أو `IMAGE_MODEL` أو `OPENAI_API_KEY`؛ راجع README الخاص بكل لغة. ملف `.env.example` مرجع للإعداد فقط، ولا تقوم جميع برامج CLI بتحميل ملف `.env` تلقائياً. عرّف المتغيرات في الطرفية أو مدير الأسرار أو بيئة التشغيل التي تستخدمها.

تتضمن أسماء النماذج المستخدمة في الأمثلة `gpt-image-2` و`gpt-image-2.5` و`gpt-image-2.5-flare` و`gpt-image-2.5-burst`. تمررها التطبيقات كمعرفات قابلة للتهيئة، لكن **لا تفترض أن كل نموذج متاح لكل حساب**. لمعرفة النماذج التي تظهر للمفتاح الحالي:

```bash
curl https://api.ai-router.dev/v1/models \
  -H "Authorization: Bearer $AI_ROUTER_API_KEY"
```

قد تختلف إتاحة هذا المسار والنماذج بحسب إعداد الخدمة والحساب. إذا لم يظهر النموذج أو أعاد خطأ صلاحيات، اختر معرفاً مسموحاً لمفتاحك. تحقّق كذلك من الأحجام ومستويات الجودة المقبولة للنموذج قبل استخدامها.

## تشغيل الأمثلة الستة

نفّذ كل مجموعة أوامر من المجلد المحدد. على Windows PowerShell عيّن المفتاح مثلاً باستخدام `$env:AI_ROUTER_API_KEY = "your-key"`. يحتاج مثال C++ إلى مترجم C++17 وCMake وملفات التطوير الخاصة بـ libcurl.

### Python

يتطلب Python 3.10 أو أحدث، ولا يحتاج إلى تثبيت اعتماد إضافي وقت التشغيل:

```bash
cd marketing/image-generation-multilang/python
export IMAGE_API_KEY="$AI_ROUTER_API_KEY"
export AI_ROUTER_BASE_URL="https://api.ai-router.dev/v1"
python main.py \
  --prompt "A glass greenhouse on a rainy rooftop, editorial photography" \
  --edit-prompt "Warm the light to golden hour without changing the architecture" \
  --output-dir ./outputs
python -m unittest discover -s tests -v
```

يحفظ المثال `outputs/generated.png` و`outputs/edited.png`. ويمكن أيضاً ضبط `IMAGE_MODEL` و`IMAGE_SIZE` و`IMAGE_QUALITY` واستخدام خيارات CLI المناظرة.

### Node.js

يتطلب Node.js 18.17 أو أحدث. يستخدم العميل واجهات Node المضمنة ولا يحتاج إلى مكتبة HTTP خارجية:

```bash
cd marketing/image-generation-multilang/nodejs
export AI_ROUTER_API_KEY="your-key"
npm test
npm run demo -- \
  --prompt "A glass greenhouse on a rainy rooftop" \
  --edit-prompt "Add warm golden-hour lighting" \
  --model gpt-image-2
```

يحفظ الناتجين في `outputs/generated.png` و`outputs/edited.png`. وتتوفر خيارات `--size` و`--quality` و`--base-url` و`--timeout` و`--output-dir`.

### C++

يتطلب C++17 وCMake 3.20 أو أحدث ومكتبة libcurl:

```bash
cd marketing/image-generation-multilang/cpp
export AI_ROUTER_API_KEY="your-key"
cmake -S . -B build -DBUILD_TESTING=ON
cmake --build build --config Release
ctest --test-dir build --output-on-failure
./build/imagegen \
  --base-url https://api.ai-router.dev/v1 \
  --model gpt-image-2 \
  --prompt "A glass spaceship product photo on a moss-covered desk" \
  --edit-prompt "Add a soft sunrise rim light and preserve the silhouette"
```

على Windows قد يكون المسار إلى البرنامج الناتج `build/Release/imagegen.exe` بحسب مولّد CMake. يتيح CLI الخيارين `--output` و`--edited-output` لتغيير مساري الملفين.

### Go

يتطلب إصدار Go المتوافق مع ملف `go.mod`:

```bash
cd marketing/image-generation-multilang/go
export AI_ROUTER_API_KEY="your-key"
go test ./...
go vet ./...
go run ./cmd/imagegen \
  --base-url https://api.ai-router.dev/v1 \
  --model gpt-image-2 \
  --prompt "A glass greenhouse on Mars at sunrise" \
  --edit-prompt "Add small warm lights without changing the composition"
```

المساران الافتراضيان هما `generated.png` و`edited.png`. ويمكن ضبط `--output` و`--edited-output` و`--size` و`--timeout` و`--response-format`.

### Rust

يتطلب Rust stable إصدار 1.80 أو أحدث. ينفذ الأمر الفرعي `workflow` مرحلتي الإنشاء والتعديل بالتتابع:

```bash
cd marketing/image-generation-multilang/rust
export AI_ROUTER_API_KEY="your-key"
cargo test
cargo run --release -- workflow \
  --prompt "A clean product photo of a red backpack" \
  --edit-prompt "Change the backpack to cobalt blue and preserve the framing" \
  --generated output/generated.png \
  --edited output/edited.png
```

يتوفر أيضاً الأمران `generate` و`edit` لتجربة كل مرحلة بصورة منفردة. ويمكن أخذ `AI_ROUTER_BASE_URL` و`AI_ROUTER_MODEL` و`AI_ROUTER_SIZE` من البيئة.

### PHP

يتطلب PHP 8.1 أو أحدث وامتدادي `curl` و`json`؛ ولا يحتاج المثال إلى حزمة runtime إضافية:

```bash
cd marketing/image-generation-multilang/php
export AI_ROUTER_API_KEY="your-key"
php bin/image-demo.php workflow \
  --prompt "A clean product photo of a red backpack" \
  --edit-prompt "Change the backpack to cobalt blue and preserve the framing" \
  --generated output/generated.png \
  --edited output/edited.png
```

يمكن تشغيل `generate` و`edit` كلٌّ على حدة أيضاً. يستخدم العميل `AI_ROUTER_BASE_URL` و`AI_ROUTER_MODEL` و`AI_ROUTER_SIZE` كإعدادات افتراضية من البيئة.

## عقد طلبات Images API

يرسل الإنشاء JSON مع ترويسة Bearer. مثال على الطلب:

```http
POST https://api.ai-router.dev/v1/images/generations
Authorization: Bearer $AI_ROUTER_API_KEY
Content-Type: application/json
```

```json
{
  "model": "gpt-image-2",
  "prompt": "A small glass greenhouse on a rainy rooftop",
  "size": "1024x1024",
  "n": 1,
  "response_format": "b64_json"
}
```

تحتوي الاستجابة الناجحة على قائمة `data`، وقد يحتوي العنصر الأول على `b64_json` أو `url` بحسب إعداد الخدمة. تحوّل تطبيقات العميل الصورة إلى بايتات وتحفظها في المسار المطلوب.

أما التعديل فيستخدم `POST /v1/images/edits` مع `multipart/form-data`. تشمل الحقول `model` و`prompt` و`size` والملف السابق في الحقل `image`؛ ويطلب المثال صيغة `b64_json` للنتيجة. اترك للمكتبة إنشاء قيمة multipart boundary ولا تضبط ترويسة `Content-Type` يدوياً من دونها. راجع [`API_CONTRACT.md`](../API_CONTRACT.md) للتفاصيل المشتركة بين اللغات.

## كتابة أوصاف قابلة للاختبار

للمقارنة الواضحة، استخدم وصفاً محدداً وقابلاً لإعادة الاستخدام. اذكر العنصر الأساسي والمكان والتكوين والإضاءة والغرض البصري؛ مثلاً: «صورة تحريرية لبيت زجاجي صغير فوق مبنى حضري بعد المطر، لقطة واسعة وضوء صباح بارد». وفي وصف التعديل، حدد ما تريد تغييره وما يجب أن يظل كما هو: «أضف انعكاسات دافئة إلى النوافذ، مع الحفاظ على شكل البيت الزجاجي وموضع الكاميرا».

غيّر عنصراً واحداً في كل خطوة، واحتفظ بالمسودة الأولى للمراجعة قبل إرسال تعديل آخر. لا تضع بيانات شخصية أو أسراراً أو معلومات عمل سرية ضمن الأوصاف. تساعد التعليمات الواضحة على الاختبار، لكنها لا تضمن تفاصيل بصرية بعينها؛ فالنتيجة تعتمد على النموذج وإعداد الحساب والخيارات المدعومة.

## الملفات والتكلفة ووقت الاستجابة

يشغّل مسار العمل الكامل **طلبين قد يكونان مدفوعين**: طلب إنشاء وطلب تعديل. تحقق من الأسعار والحصص والأحجام وسياسة الاحتفاظ بالبيانات في حسابك قبل الأتمتة. لا ينفذ demo إعادة المحاولة تلقائياً، لأن محاولة جديدة قد تنشئ نتيجة أخرى وتضيف تكلفة. تحفظ مرحلة الإنشاء قبل التعديل؛ وإذا فشل التعديل، يبقى الملف الأول صالحاً للمراجعة أو لإعادة الإرسال.

تحفظ النتائج محلياً تحت مجلد `output` أو `outputs` أو في المسارات التي يحددها CLI، بحسب اللغة. افحص `.gitignore` قبل مشاركة المشروع، ولا تنشر صوراً خاصة أو مواد لا تملك حق استخدامها. تستخدم الأمثلة امتداد `.png` افتراضياً؛ تحقّق من MIME ومحتوى الاستجابة قبل افتراض صيغة معينة في منتج حقيقي.

## استكشاف الأخطاء

| العَرَض | ما ينبغي فحصه |
| --- | --- |
| `401` أو `403` | هل عُرّف المتغير في الطرفية نفسها؟ هل المفتاح صالح ومصرح للنموذج؟ تجنب المسافات الزائدة وعلامات الاقتباس داخل القيمة. |
| نموذج غير موجود أو غير مصرح | استعلم عن `/v1/models` باستخدام المفتاح نفسه واختر معرفاً متاحاً للحساب. |
| رفض الحجم أو الجودة | ابدأ بـ `1024x1024` واستخدم `auto` حين يكون مقبولاً؛ راجع خيارات النموذج والحساب. |
| لا توجد صورة في الاستجابة | راجع رمز HTTP ورسالة الخطأ المحدودة ومعرف الطلب إن توفر. تحقق من `data[0].b64_json` أو رابط تقبله عملية العميل. |
| فشل التعديل بعد نجاح الإنشاء | تحقق من وجود الصورة الأولى وإمكانية قراءتها، ومن اسم حقل الرفع `image` وقبول البوابة لنوع الملف وحجمه. لا تحذف المسودة الناجحة. |
| انتهاء المهلة | قد يستغرق الإنشاء وقتاً؛ استخدم خيار المهلة المتاح وتحقق من الاتصال. لا تكرر الطلب عشوائياً إذا كان من الممكن أن الخادم أكمله بالفعل. |
| CMake لا يجد curl أو المترجم | ثبت مترجم C++17 وCMake وملفات تطوير libcurl، وتحقق من إعداد toolchain أو vcpkg على Windows. |

تستخدم اختبارات البروتوكول المحلية خادماً أو بيانات اختبار ولا تحتاج إلى مفتاح حقيقي؛ لكنها لا تثبت أن النموذج متاح لحسابك. شغّل اختبارات المجلد المختار قبل دمج العميل في تطبيقك.

## الأمن والخصوصية

- أبق مفاتيح API خارج المصدر ومستودع Git وواجهة المتصفح. استخدم متغيرات البيئة محلياً ومدير أسرار في الإنتاج.
- استخدم HTTPS. لا تمرر ترويسة Bearer إلى مضيف خارجي عند تنزيل صورة من `url`؛ تتجنب العملاء إعادة إرسال الاعتماد إلى مضيف الملف.
- تعامل مع الأوصاف والصور على أنها بيانات قد تكون حساسة. قلل السجلات، وحدد مدة الاحتفاظ، واشرح للمستخدم أين ترسل الملفات.
- تحقق على الخادم من MIME والأبعاد وحجم الرفع. المثال التعليمي ليس خدمة عامة لرفع الملفات ولا يغني عن المصادقة والحصص وضوابط الإساءة ومراجعة المحتوى.
- تأكد من امتلاك حقوق صور الإدخال والتزم بسياسات الخدمة والقوانين ذات الصلة. راجع المحتوى الناتج قبل نشره.

## من المثال إلى الإنتاج

احتفظ بعميل API واستبدل CLI بمسار خادمي موثّق للمستخدم. استخدم تخزين كائنات دائماً مع سياسة حذف مناسبة بدلاً من قرص حاوية مؤقت؛ وطبّق حصصاً لكل مستخدم ومهل اتصال وإلغاءً للطلبات. سجّل معرفات الطلبات لأغراض الدعم من دون الأسرار، وأضف مؤشرات تشغيلية ومراقبة. عند استخدام طوابير للمهام الطويلة، افصل طلب الويب عن عملية التوليد. لا تضف إعادة المحاولة إلا بحدود واضحة وبعد تحديد الأخطاء القابلة لإعادة المحاولة، واختبر السيناريوهات باستخدام ردود اصطناعية قبل السماح بإنفاق فعلي.

## متابعة المشروع واكتشاف AI-ROUTER

إذا كنت تبحث عن واجهة متوافقة مع OpenAI لربط توليد الصور وتعديلها بلغات متعددة، فزر [AI-ROUTER باللغة العربية](https://ai-router.dev/ar) لمعرفة معلومات المنصة والوصول إلى الحساب وإتاحة النماذج الحالية. عنوان API المستخدم في هذا المثال هو `https://api.ai-router.dev/v1`.

المحتوى والكود لأغراض تعليمية؛ ولا يمثلان اختباراً مستقلاً لجودة النماذج ولا وعداً بتحسين الظهور أو الترتيب في محركات البحث أو بتكلفة أو إتاحة محددة. عند الإشارة إلى المثال، اجعل رابط الموقع ذا صلة ومفيداً للقارئ؛ قد تساعد الروابط التحريرية الطبيعية على اكتشاف المشروع، لكن لا يمكن ضمان ترتيب البحث بوساطة صياغة تسويقية. لإضافة لغة أخرى، اتبع [`CONTRIBUTING.md`](../../CONTRIBUTING.md)، وحافظ على العقد المشترك وأضف اختبارات لا تتصل بخدمة مدفوعة.
